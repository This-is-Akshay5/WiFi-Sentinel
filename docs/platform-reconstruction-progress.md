# WiFiSentinel Reconstruction Progress

## Project state

- Source is the existing Python/PyWebView desktop app with a SQLite store, vanilla HTML/CSS/JavaScript UI, native macOS/Windows wireless adapters, Nmap, offline PCAP analysis, reports, and a macOS packaging workflow. This does not mean all capabilities in the master prompt are implemented on both operating systems.
- The user's master prompt locks a broader product direction: retain Wi-Fi/network assessment while incrementally adding LAN intelligence, a white-box/black-box web analyzer, evidence-linked attack paths, controlled awareness simulation, messaging through enrolled receivers, and retesting.
- Kali and the remote Kali connector are obsolete and have been removed from the active runtime, UI, catalog, configuration template, and dedicated tests. The existing `.env`, application databases, reports, captures, and historical observations were not edited or cleared. Old observation provenance remains historical data.
- Existing source tree has no Git metadata. The installed application database migrated additively from schema 14 to **schema 15** when the final rebuilt app launched; read-only integrity/count checks confirmed existing assessments, executions, findings, evidence, captures, and observations remained.

## Completed in this reconstruction session

- Replaced connector-based Wi-Fi fallback with native OS scan state and kept permission failures / empty results explicit.
- Removed remote-only assessment catalog entries and connector gates. Existing local Nmap execution remains.
- Reworked local tool detection for Nmap, TShark, tcpdump, Aircrack-ng, hcxtools, Bettercap, and Wireshark. Tool detection is not treated as tool integration.
- Removed connector settings and remote tool/inventory UI; retained theme and OpenAI settings.
- Removed obsolete connector client/service/source and connector-only tests; rewrote permission-state tests around native observations.
- Removed Kali-specific environment variables from `.env.example` and removed active setup instructions. The user's `.env` file was not inspected or changed.
- Added additive schema 12 engagement manifests and append-only scope-change history. Active network tests are gated by recorded authorization, timezone-aware engagement dates, explicit permitted test IDs, optional in-window intervals, and excluded hosts/devices/CIDRs. Scope UI exposes the main fields; authorization documents and recurrent calendar schedules remain unfinished.
- Added a new LAN Inventory page using the existing OS neighbor-cache and bounded authorized ICMP paths; source records remain separate and unknown identity claims are avoided.
- Added a working one-page web surface snapshot route with explicit authorization, HTTP/HTTPS validation, query/credential rejection, DNS pinning, same-origin redirect checks, a response-size cap, no form submissions, cookie-value suppression, and persisted findings/evidence. This is not a full crawler or vulnerability scanner.
- Added a working read-only static source review route: native file selection, per-file and total size bounds, explicit ownership/authorization, deterministic secret-literal/dynamic-execution review indicators, safe result redaction, and persisted evidence/findings. No selected code is executed.
- Added a bounded one-page HTTP/HTTPS metadata snapshot route with authorization, same-origin redirect limits, DNS pinning, response-size limits, and evidence persistence. It does not crawl or submit forms.
- Added an Approved Access Point Inventory workflow. Operators can maintain exact unicast BSSIDs and compare them with completed OS scan rows inside an assessment's declared wireless scope. Unlisted BSSIDs create low-confidence informational review findings with persisted source-labelled evidence; they are never called confirmed rogue APs. Duplicate SSIDs are not treated as findings.
- Added a Device Intelligence page that reads persisted OS neighbor-cache snapshots, bounded ICMP discovery runs, scoped neighbor-cache assessment records, and Nmap evidence as separate observation profiles. It preserves per-field source/status, exposes only persisted open services, and labels Nmap service fingerprints as estimates. Profiles are never merged into unique or permanent device identities. Router/DHCP and mDNS remain unavailable.
- Extended offline PCAP analysis with bounded DNS-question metadata (query name/type, client/resolver IP, timestamp, and BSSID where present). Query names are persisted only when the exact wireless SSID/BSSID scope matches; unscoped and out-of-scope names are withheld. The feature does not decode DNS answers, TLS, DoH/DoT, or application payloads.
- Added **Reachability & Segmentation Review** for max 8 literal in-scope IPs and max 4 TCP ports. The backend requires recorded authorization, an active timezone-aware scope window, explicit `segmentation_reachability` permission, and target/exclusion checks before connecting. Probes originate from the current host, send no application payload, and timeouts remain inconclusive. Evidence and any direct mismatch findings are persisted.
- Added **Authorization Documents** for assessments: safe native picker, bounded local copy, SHA-256/provenance, audited soft removal, metadata-only report output, and no content/path returned to the UI. This remains local authorization evidence; the content is not machine-validated.
- Expanded **Web Crawl** to at most 20 unauthenticated same-origin GET pages. It revalidates redirects and pinned destination addresses, records an observed route/status/content-type inventory, and labels API-looking paths as heuristics. Forms, query strings, scripts, credentials, and state-changing methods are excluded.
- Expanded **Repository Review** from selected files to a native repository-folder workflow. It avoids symlinks, generated/dependency trees, `.env` and common key/credential files; caps the review at 500 files, 25 MiB total, and 2 MiB per file; redacts matched literals; and inventories local dependency manifests without network advisories or code execution.
- Added **Evidence Correlation**. The graph has nodes for persisted findings/evidence and edges only for direct finding-to-evidence references. Multiple findings sharing the same explicit asset are shown as theoretical candidates. No ordered exploit chain is claimed or generated because validated transition/precondition relations are absent.
- Added **Awareness Training**, an original fixed synthetic exercise hosted on loopback (`127.0.0.1`) only. It accepts visit/click/synthetic yes-no events, rejects extra/free-form fields, expires within 30 minutes, persists event counts without participant IPs or raw tokens, stops on request/restart, and offers a 90-day inactive-history purge.
- Added data recovery for interrupted training sessions: restarting the application marks any persisted active local listener as stopped while retaining event counts.
- Added **LAN Messaging** for an explicitly enrolled compatible receiver. Announcements carry a receiver-bound ID, nonce, issue/expiry times, and HMAC signature; remote receivers require HTTPS with exact certificate pinning. WiFiSentinel reports `acknowledged` only after validating the receiver's HMAC acknowledgement. The supplied standard-library receiver is cross-platform Python, but it displays in its terminal, not an OS notification. Receiver enrollment tokens and message bodies are not persisted; history stores receiver, status, timestamp, message ID, and content digest. Re-enrollment is required after restarting the desktop app.
- Added **selected-finding retests** for findings linked to a supported assessment-catalog execution. Retests reuse the original target and only the previously open Nmap ports from persisted evidence, require the exact original assessment scope to remain unchanged, and flow through the engine's current authorization and target gates. `fixed` requires rule-specific conclusive negative evidence (for example, the same Nmap host is up and all previously open ports are closed); an absent host, partial state summary, blocked run, or unsupported detector is `unable_to_verify`. Outcomes are stored separately with fresh evidence/execution references: `fixed`, `partial`, `unresolved`, or `unable_to_verify`. Retest history is present in JSON/PDF/CSV assessment exports. Findings from non-catalog workflows and legacy records without scope-linked evidence remain unable to verify.
- Added additive schema **v15** for immutable finding-retest history. Existing finding rows are retained; each retest links to the original finding and, where available, a new execution and evidence record.

## Remaining implementation work

The master prompt is a multi-milestone product roadmap and is **not complete**. The web and repository analyzers are bounded read-only workflows, not full authenticated vulnerability scanners or advisory audits. Engagement calendar/contact workflows remain. Device Intelligence does not implement router/DHCP or mDNS discovery, richer OS fingerprinting, or stable device tracking. Traffic analysis covers offline packet/protocol/endpoints and in-scope DNS questions only; live capture, traffic volume/flow summaries, and a traffic dashboard remain open. Reachability is a bounded TCP connect from the current host; remote source-segment tests, ICMP matrices, route verification, and VLAN attribution remain open. Evidence Correlation does not generate ordered attack paths or AI explanations. Awareness Training is loopback-only and stores aggregate synthetic choices; it has one active session at a time and does not distribute email or host exercises on a LAN. LAN Messaging currently supports only the supplied enrolled receiver client; there is no OS popup or human-read proof, no persistent enrollment, and physical cross-host TLS was not verified. Selected catalog finding retests now compare same-scope fresh results, but there is no full cross-workflow finding normalization, attestation, or retest support for source/web/capture/AP findings without catalog execution links. Windows physical hardware, app packaging/launch, and cross-platform UI behavior remain unverified on Windows hardware.

Current project entry points remain `./run_simulator.command` on macOS and `run_simulator.bat` on Windows. The launch scripts themselves were not exercised in this turn. The rebuilt temporary macOS bundle was launched and its primary changed navigation routes were inspected.
